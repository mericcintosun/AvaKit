Studio's one-action-at-a-time rule now holds across every Studio process: the dashboard and `avakit-studio mcp` share a lock file (`~/.avakit-studio/action.lock`), so an agent and a click in the dashboard can no longer run avalanche-cli at the same time, and both refuse with the same "Another action (…) is still running" message. Launching a local L1 or deploying to Fuji under a name whose existing config has another chain ID or token is refused with the existing values named, instead of deploying the old chain and reporting the new values as done; a matching config is reused and the log says so. The Fuji wizard only moves on (and only transfers testnet AVAX) once the name, chain ID, token and amount pass the server's own rules, and the chain ID and token stay editable until the deploy has run. Interchain's `ready` (dashboard, `/api/icm/state` and the `icm_state` tool) is now true only when two messengers are deployed and linked — the new `hasPeers` says that two L1s are running — and the Overview card and Devnet banner say "deploy the messengers to send a message" until then. An open tab shows a stopped or restarted Studio as disconnected within one status poll.
